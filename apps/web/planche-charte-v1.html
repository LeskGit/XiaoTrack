5BDomaines

Une teinte par onglet, appliquée uniquement à la tuile d'icône (fond doux, icône teintée ; tuile pleine quand l'onglet est actif). Jamais sur les boutons, les textes ou les graphiques.

Tension assumée : avec cinq domaines, des voisinages sont inévitables. Notes (jaune) frôle l'alerte (ambre), Planning (ciel) frôle l'info (bleu), Workouts (rose) frôle le danger (rouge). La règle qui évite la confusion : une couleur de domaine n'apparaît que sur une tuile d'icône, une couleur de statut n'apparaît jamais sans son icône ni son texte.

9AMouvement : expressif

On garde tout : cascade d'entrée des widgets, chiffres qui comptent, courbes qui se dessinent, anneau qui se remplit, barre d'édition qui rebondit, pastille qui pulse. Le bouton « Rejouer les animations » relance l'aperçu. Les courbes et les durées restent celles de l'app.

6BRègles qui rendent le mode sombre possible plus tard

  • Aucune couleur en dur dans un composant : ni rgb(), ni oklch(), ni bg-sky-50. Uniquement des tokens (bg-surface, text-ink-muted, var(--color-data-1)).
  • Les ombres passent par --shadow-tint : le jour du mode sombre, une seule variable change.
  • Le texte a ses propres tokens (ink, ink-soft, ink-muted) au lieu de gray-900, gray-600, gray-400.
  • Chaque nouvelle couleur entre d'abord dans @theme, avec un nom de rôle, jamais de teinte.
